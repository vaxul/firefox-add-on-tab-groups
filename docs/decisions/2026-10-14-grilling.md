# Entscheidungen aus der Grilling-Session (2026-10-14)

Ausgangspunkt: Nachfolger von [Panorama Tab Groups](https://github.com/vaxul/panorama-tab-groups)
(v0.8.11, MV2, letzter Commit 2020-05). Übernommen wird nur das Konzept der Popup-View; die
Freeform-View entfällt.

## Getroffene Entscheidungen

### E1 – Nur Firefox
Andere Browser werden ignoriert. Kernmechanismus (`tabs.hide`/`tabs.show`) und Persistenz
(`sessions.set/getTabValue`, `set/getWindowValue`) sind Firefox-only; eine Abstraktionsschicht
für andere Browser wird nicht gebaut.

### E2 – Native Firefox-Tabgruppen werden beim Gruppenwechsel aufgelöst und wiederhergestellt
Beobachtung im alten Add-on: Die Tabs einer nativen Gruppe werden ausgeblendet, das Gruppen-Label
bleibt in der Tableiste stehen; ein Klick darauf öffnet nichts. Die `tabGroups`-API kennt keinen
Hidden-Zustand (`update` nur `collapsed`, `color`, `title`).

Lösung: Beim Ausblenden einer Panorama-Gruppe werden ihre nativen Gruppen per `tabs.ungroup`
aufgelöst, beim Einblenden per `tabs.group` + `tabGroups.update` wiederhergestellt.

- Der Zustand jeder nativen Gruppe (Titel, Farbe, collapsed, Reihenfolge, eigener stabiler
  Schlüssel) wird per `sessions.setTabValue` an jedem Tab persistiert, damit ein Absturz oder
  Neustart im aufgelösten Zustand nichts verliert. Die native Gruppen-ID ist nach Session-Restore
  nicht stabil und taugt nicht als Schlüssel.

### E3 – Eine native Gruppe gehört vollständig zu genau einer Panorama-Gruppe
- Wird ein Tab in eine andere Panorama-Gruppe verschoben, verlässt er seine native Gruppe.
- Konfliktregel: Enthält eine native Gruppe Tabs aus mehreren Panorama-Gruppen (z. B. durch
  Drag in der Tableiste), bestimmt der **erste Tab** der nativen Gruppe die Panorama-Gruppe; die
  übrigen Tabs werden dorthin umgehängt.

### E4 – Migration über Backup-Import mit Abgleich gegen offene Tabs
Die neue Extension kann die `sessions`-Werte des alten Add-ons nicht lesen (andere Extension-ID,
keine Export-Schnittstelle). Migrationsquelle ist der Backup-Export des alten Add-ons
(`panoramaView` v1).

Import gleicht in-place ab statt neue Fenster zu öffnen:
1. Backup-Fenster ↔ offene Fenster nach höchstem URL-Überlapp zuordnen.
2. Pro Fenster Tabs nach URL + Reihenfolge abgleichen; doppelte URLs der Reihe nach.
3. Treffer: Gruppe und `groupId` setzen.
4. Fehlende Backup-Tabs als `discarded` in ihrer Gruppe anlegen (abschaltbar).
5. Offene Tabs ohne Treffer kommen in eine Gruppe „Unsortiert“.

Der klassische Import „in neuen Fenstern“ bleibt für echte Backups erhalten.

Nutzerablauf: Backup im alten Add-on exportieren → neue Extension installieren und Backup
importieren → altes Add-on deinstallieren.

### E5 – Phasenschnitt
| Phase | Inhalt |
|---|---|
| 1 – Kern + Migration | Background-Logik (Gruppen pro Fenster, neue Tabs erben aktive Gruppe, Ein-/Ausblenden, E2/E3), Import mit Abgleich (E4), minimales Popup (Liste, wechseln, anlegen, umbenennen, schließen inkl. letzte/leere Gruppe), Badge + Tooltip |
| 2 – Parität zum alten Popup | Detailansicht mit Tabliste, Suche (literal, kein RegExp), Drag & Drop der Gruppenreihenfolge, Kontextmenü „Tab an Gruppe senden“, Shortcuts nächste/vorherige Gruppe, Theme, Export `panoramaView` v1 |
| 3 – Erweiterungen | optional |

### E6 – Stack
- Manifest V3, `background.scripts` als nicht-persistente Event-Page; kein Zustand im Speicher.
- TypeScript + esbuild; kein UI-Framework, DOM-Aufbau mit `textContent` statt HTML-Strings.
- Tests: `vitest` mit In-Memory-Fake von `tabs`, `sessions`, `tabGroups`; `web-ext` für
  lint/run/build; E2E später per WebDriver BiDi (`selenium-webdriver`).
- `strict_min_version: "139.0"` (laut `@mdn/browser-compat-data` 8.1.5: `tabs.group`/`ungroup`
  seit 138, `tabGroups` seit 139).

### E7 – Identität und Veröffentlichung
- Arbeitstitel „Tab Groups“; „Panorama“ wird nicht verwendet.
- Gecko-ID `tab-groups@vaxul.github.io` (nach erster AMO-Signierung nicht mehr änderbar).
- Lizenz MPL 2.0 (erlaubt Übernahme von Locales, `getPluralForm`, Konvertierung alter
  „Tab Groups“-Backups).
- Zunächst unlisted auf AMO signiert; öffentliches Listing frühestens nach Phase 2.

## Annahmen (nicht explizit besprochen, im Spec zu bestätigen)

- A1: Gruppen bleiben pro Fenster (wie im alten Add-on).
- A2: Angepinnte Tabs gehören zu keiner Gruppe und bleiben immer sichtbar.
- A3: Tabs mit aktivem Mikrofon/Kamera lassen sich nicht ausblenden (`tabs.hide`-Einschränkung);
  sie bleiben sichtbar und werden im Popup markiert.
- A4: Private Fenster werden unterstützt; Gruppen dort überleben keinen Neustart.
- A5: Schließen der letzten Gruppe legt eine neue leere Standardgruppe an; das Öffnen einer
  leeren Gruppe legt einen neuen Tab in ihr an.
- A6: Group-IDs werden einheitlich über einen Zähler pro Fenster vergeben (im alten Code
  inkonsistent zwischen Background und Popup).

## Offene Punkte zur Verifikation in Phase 1

- V1: Verhalten von `tabs.ungroup`/`tabs.group` auf ausgeblendete Tabs und Reihenfolge der
  Aufrufe (erst ungroup, dann hide bzw. erst show, dann group) praktisch prüfen.
- V2: Ob Firefox beim Auflösen per `tabs.ungroup` Einträge unter „gespeicherte Gruppen“ anlegt
  (sollte nicht passieren; nur Schließen über die UI speichert).
- V3: Reaktion auf `tabGroups.onCreated`/`onUpdated`, die die Extension selbst auslöst
  (Rückkopplung vermeiden).

## Nachtrag: Revisionen in der Inception (2026-10-14)

Die Inception hat folgende Punkte geändert; maßgeblich sind ab jetzt `docs/vision.md`,
`docs/constitution.md` und `docs/roadmap.md`.

- A1 ersetzt: Gruppen sind global wie in Simple Tab Groups. Jedes Fenster zeigt genau eine
  Gruppe, eine Gruppe ist in höchstens einem Fenster offen.
- E5 ersetzt: sechs Phasen statt drei; „Tabs verschieben“ (alle markierten Tabs,
  Gruppenliste im Kontextmenü immer aktuell) gehört in den Kern. Erweiterungen kommen
  später über `/loopkit:roadmap`.
- E5 Export: eigenes Backup-Format v1 statt `panoramaView` v1; `panoramaView` v1/v2 bleibt
  Importquelle.
- E6 `strict_min_version`: 140.0 (ESR) statt 139.0, `gecko_android` 142.0 — AMO verlangt
  `data_collection_permissions`, das erst ab 140 (Android 142) unterstützt wird.
- Neues Ziel: Theme hell/dunkel im aktuellen Firefox-Stil.
- V1 und V2 laut `docs/BEHAVIOR-TABGROUPS.md` von Simple Tab Groups (getestet auf Firefox 154)
  beantwortet: erst `ungroup`, dann `hide`; erst `show`, dann `group`. `tabs.ungroup` legt
  keine gespeicherten Gruppen an, `tabs.remove` über eine ganze Gruppe schon. Praktische
  Bestätigung bleibt Teil von Phase 2.
